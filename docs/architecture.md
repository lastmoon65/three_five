# 《红心对决》总体架构设计

- 版本：v1.1（2026-08-03）
- 依据：规则 V8.3、PRD V7.0、可行性评审报告、部署方案对比
- 设计原则：最简单优先；单机版先行；4 人私玩、低并发、无商业化

## 0. 开发路线：单机版先行

1. 先做单机版（同屏轮流）：规则引擎 + 五区游戏页，跑通完整一副流程。
2. 规则引擎做成无依赖纯 JS 模块（浏览器 / Node 双端可运行），单机版与联网版共用同一份引擎，杜绝"规则两套"。
3. 联网版只在引擎外增加：WS 通道、房间、鉴权、断线重连；引擎零改动。

## 1. 架构总览

单服务器、双端：

- 前端：静态 H5（public/），原生 HTML/CSS/JS，无构建工具
- 后端：Node.js 单进程，HTTP（托管静态资源）+ WebSocket（全部业务消息）
- 存储：全部内存；固定账户写在 config.js；不持久化战绩
- 第三方依赖：仅 ws（WebSocket）

```
浏览器(H5) ──WSS──▶ Node.js 服务
                     ├─ 静态资源托管 (public/)
                     ├─ 连接与会话 (token)
                     ├─ 房间管理 (room)
                     └─ 规则引擎 (game) ← 唯一裁决方
```

## 2. 模块划分

| 模块 | 职责 | 归属 |
| --- | --- | --- |
| 页面 | 登录/大厅/房间/游戏/结算 UI 与动画 | 前端 |
| WS 客户端 | 连接、心跳、重连、事件渲染 | 前端 |
| 连接与鉴权 | 固定账户校验、token 签发、单会话 | 后端 |
| 房间模块 | 创建/加入/准备/离开/解散 | 后端 |
| 规则引擎 | 发牌/亮牌/进贡/埋底/打牌/结算（纯函数，可单测） | 后端 |
| 广播 | 状态事件推送房间内玩家 | 后端 |

## 3. 技术选型

- 后端：Node.js（>=18）+ ws，无框架
- 前端：原生 HTML/CSS/JS（ES Modules），无框架无构建
- 存储：内存 Map；账户来自 config.js（4 个固定账号）
- 运行：`node server.js`，监听 8080

## 4. 部署

- 方式A（推荐）：本机运行 + 内网穿透（朋友浏览器直开，手机可连）
- 方式B：本机运行 + Tailscale 组网
- 方式C：轻量云服务器（国内需备案，香港无需；切换环境即可，无代码改动）
- 端口用 8080 等非 80 端口，避开家庭宽带运营商限制
- HTTPS：Tailscale 自带加密；穿透由服务商提供；云方案用免费证书

## 5. 安全与防作弊边界

1. 服务端唯一权威：所有裁决在规则引擎，客户端只提交意图。
2. 最小化数据：只下发本人手牌；其他玩家只下发 handCount 与公开信息。
3. 会话：登录得 token（内存），WS 连接以 token 鉴权，绑定账户。
4. 房间：6 位房号；游戏中锁定，禁止加入/换人。
5. 事件防伪造：客户端消息仅为"请求"；状态一律由服务端广播。
6. 单会话：同一账户重复登录时顶掉旧连接。

## 6. 简化决策（与 PRD 的差异）

| 项 | PRD 原案 | 本次决定 |
| --- | --- | --- |
| 暂停机制 | 队伍共享暂停 1 次 30 秒 | 不实现 |
| 断线 | 30 秒窗口/单局 3 次 | 无限等待重连，不代打、不判负 |
| 房主断线 | 自动解散 | 等待重连；仅主动离开才解散 |
| 战绩 | 未明确 | 不持久化 |
| 通信 | REST + WS 混合 | 全部走 WebSocket 单通道 |
| 开发顺序 | 直接联网版 | 单机版先行（见第 0 章） |
