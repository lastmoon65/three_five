# 网络同步设计（快照 + seq + 心跳 + 重连）

- 版本：v1（2026-08-03）
- 结论：网络抖动/断开不能导致四家局面不一致；断线必须可恢复。这套机制决定游戏能否成立。

## 1. 核心模型

1. **服务端是唯一状态源**（不是防作弊，而是保证四家看到同一副牌局）。
2. **全量快照广播**：每一步都广播完整局面（game_state），不是"张三出了A"这类增量事件。
3. **前端幂等重绘**：客户端永远以"最新收到的快照"整体重绘，不依赖历史、不自己裁决。
4. **快照带序号（seq）**：每房间维护单调递增序号，客户端丢弃过期快照。
5. **重连重发**：断线重连成功后，服务端立即重发当前完整快照。

## 2. 失败场景与处理

| 场景 | 表现 | 处理 |
| --- | --- | --- |
| 网络抖动（延迟） | 某端界面暂时落后 | 快照自愈：收到最新快照整体重绘，直接跳到最新，不补中间步骤 |
| 单条消息丢失（连接未断） | 几乎不发生（TCP 有序可靠） | 下一条快照即全量，直接追平 |
| 连接断开 | 客户端 onclose | token 重连 → 服务端重发当前快照 |
| 重连交错（新旧快照在途） | 旧快照可能晚到 | game_state 带 seq，客户端丢弃 seq ≤ 当前的快照 |
| 半开连接（假死） | 双方都不知断开 | 服务端 ws 心跳 ping/pong，超时 terminate → 标记离线并广播；浏览器自动回 pong |

## 3. 服务端实现

- `room.seq`：每个房间一个单调递增计数器；`broadcastGameState` 每次 `seq++` 并随快照下发。
- 心跳：`setInterval` 每 30 秒对所有连接 `ping()`；若上一轮未收到 `pong` 则 `terminate()`（触发 close 处理器：标记离线 + 广播）。
- 重连：`afterAuth` 中若用户在房间且对局存在，重发 room_updated + game_state（含当前 seq）。
- 对局数据分层：公开层（桌面/维度/赢家/分数/阶段/谁行动）+ 个人层（自己的手牌 + 当前合法出牌提示）。

## 4. 客户端实现

- 记录 `lastSeq`；收到 game_state 时，若 `seq <= lastSeq` 则丢弃；否则更新并重绘。
- 换房间/重新登录时重置 `lastSeq = 0`。
- 渲染必须幂等：同样的快照渲染出同样的界面。
- 断线自动重连（已有）：重连成功后以服务端快照为准恢复。

## 5. 验收标准

- 任意动作后，所有在线的客户端最终收到同一序号的快照。
- 重连后客户端局面与服务端一致（测试已覆盖）。
- 半开连接在心跳超时后被清理并标记离线。
- 打牌全程（发牌→亮牌→进贡→埋底→打牌→结算）不依赖增量补发。
