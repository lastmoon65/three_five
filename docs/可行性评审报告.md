# 《红心对决》架构师可行性评审报告

- 版本：v1（2026-08-03）
- 评审人：hongxin-architect
- 输入：PRD V7.0、规则 V8.3、部署意向（阿里云 + 自有域名 + 网页版 + 4人私玩 + 无赌博）

## 1. 结论

**可行。** 技术、成本、规模均无问题；合规上需要选对部署路径（建议用境外节点），并守住三条红线：非经营、无赌博、不公开。

## 2. 合规评估（最优先）

### 2.1 关键事实

- 域名解析到中国大陆服务器，必须办理 ICP 备案；阿里云会阻断未备案域名的 80/443 访问。
- 面向公众提供下载、注册、充值等服务的网络游戏，需取得游戏版号（电子出版物审批）等前置审批；个人主体基本无法取得。
- 不以营利为目的、无财物输赢的纯娱乐活动，不构成赌博；但产品绝不能出现充值、兑换、筹码变现等任何功能。

### 2.2 主要风险

- 国内服务器 + 网站内容含"棋牌"，备案时管局可能要求游戏前置审批 → 个人办不下来 → 备案被拒或网站被要求关停。
- 即使不收费，未备案域名解析到国内节点会被拦截；已备案但被认定经营游戏，同样有处罚风险。

### 2.3 推荐路径

- 方案A（推荐）：阿里云**香港**轻量服务器 + 现有域名解析到境外节点（无需备案）+ HTTPS。四人小圈子访问延迟可接受，合规摩擦最小。
- 方案B：国内服务器 + ICP 备案，网站按"非经营性个人网站"如实填报，不出现游戏/棋牌运营表述；风险自负（可能被要求提供版号）。
- 产品红线：不开放注册、不收费、不推广、无任何充值/兑换；固定账户白名单（PRD 已设计）。

## 3. 技术可行性

### 3.1 规模评估

4 人同时在线、单桌对局、极低并发。单台 2C2G 轻量服务器绰绰有余，无需复杂基础设施。

### 3.2 架构骨架（初步）

- 前端：H5 SPA（推荐 Vue3 或 React），静态资源由 Nginx 托管。
- 后端：推荐 Node.js（NestJS）或 Python（FastAPI）；REST（登录/房间）+ WebSocket/WSS（实时状态）。
- 数据：SQLite 持久化账户与配置；房间/对局状态放内存（重启即清，适合小圈子）。
- 安全：固定账户 + Token 会话、服务端权威裁决、手牌最小化下发（他方手牌永不出服务器）、HTTPS/WSS。
- 部署：阿里云轻量服务器 + Nginx 反代 + 免费 HTTPS 证书 + systemd/Docker。

### 3.3 成本估算

- 服务器：轻量应用服务器约 30~100 元/月（香港节点略高于国内同配置）。
- 域名：已购；HTTPS 证书免费。
- 总计：约 500~1500 元/年。

## 4. 输入文档核对

- 规则 V8.3：已闭环。54 张牌力全覆盖、六种出牌维度、进贡/埋底/轮庄/造反全部有唯一裁决，满足架构设计前提。
- PRD V7.0：登录/大厅/房间/游戏主流程完整；第六~十幕 UI 细节留待专项 PRD，不影响状态机与契约先行。
- 断线重连（30秒/3次）与"一键满员"测试通道已定义，架构中按此实现。

## 5. 决策清单（待产品方拍板）

1. 部署地域：香港节点（推荐） vs 国内 + ICP 备案。
2. 后端技术栈：Node.js vs Python。
3. 战绩持久化：是否保存历史战绩（建议仅保留最近若干局，或不做）。
4. 暂停机制：PRD 5.2"队伍共享暂停（1次/30秒）"的具体规则未定义——谁可发起、何时可用、两队各 1 次还是共用？需要产品定义。
5. 断线托管策略：断线 30 秒内是否自动代打？代打怎么出牌（按最小牌/最大牌）？超时/3次用尽后的处理（判负/解散）？
