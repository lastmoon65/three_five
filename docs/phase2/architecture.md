# 《红心对决》二期总体架构设计（6 人两副牌模式）

- 版本：v2.0（2026-08-03）
- 依据：规则 V8.3（4 人）、规则 V9 草案（6 人两副牌）、docs/architecture.md v1.1
- 原则：**4 人模式零回归；二期纯增量；公网（deploy-live）与开发目录物理隔离**

## 0. 二期范围

| 项 | 内容 |
| --- | --- |
| 新增 | 6 人两副牌模式（108 张、每人 17 张、底牌 6 张、3v3 隔人一队） |
| 新增 | 模式选择入口（登录后第一步选 4 人 / 6 人） |
| 新增 | 房间号隔离（4 人 4 位 / 6 人 6 位，互不互通） |
| 不动 | 4 人模式全部代码行为、规则、房间流程 |
| 复用 | 断线重连、seq 快照、心跳、鉴权、房间基本框架、部署拓扑 |

## 1. 架构总览（与一期一致，仅扩展）

单服务器、双端、无框架：

```
浏览器(H5) ──WS──▶ Node.js 服务
                     ├─ 静态资源托管 (public-net/)
                     ├─ 连接与会话 (token, 单会话)
                     ├─ 房间管理 (room: mode p4|p6, 座位 4|6)
                     ├─ 规则引擎 core（共用裁决函数）
                     ├─ 规则引擎 Game（4 人，原样保留）
                     └─ 规则引擎 Game6（6 人两副牌，新增）
```

## 2. 模块划分

| 模块 | 变更 | 职责 |
| --- | --- | --- |
| `game/core.mjs` | **新增（抽取）** | 牌力、牌组构造、维度合法性、墩裁决、甩牌前 N 张、四清垫分等纯函数；**对重复牌天然兼容** |
| `game/game.mjs` | 重构（只抽取不换行为） | 4 人引擎改为调用 core，行为与 V8.3 完全一致 |
| `game/game6.mjs` | **新增** | 6 人引擎：发牌/亮牌/分层造反/三进贡/埋底/打牌/轮庄，调用 core |
| `net-server.mjs` | 修改 | room 增加 mode、房号按模式生成、6 座房间、开局条件 6 人 |
| `public-net/` | 修改 | 模式选择页、6 人房间/游戏 UI（17 张手牌、5 对手） |
| `config.mjs` | 不变 | 账号通用，两种模式共用 |
| `deploy-live/` | 不变 | 公网独立副本；二期开发完才同步 |

## 3. 关键设计决策

### 3.1 引擎：共享 core + 双引擎，不把 Game 参数化

- 一期 Game 把 4 人/对家/12 张/单副牌硬编码进流程；改成"万能参数化引擎"改动大、回归风险高。
- 二期采用：**裁决逻辑下沉到 core，流程逻辑各自实现**。
  - core 里的牌力表、同牌力先出者大、维度裁决、甩牌前 N 张、真杠/假杠/四清校验，与人数无关，两副牌下按 id 不依赖唯一性，直接可复用。
  - Game6 复用 core，自行实现：6 人轮转（逆时针下家 `(seat+5)%6`）、3v3 队伍（`team = seatId % 2`，座位 0/2/4 对 1/3/5）、对位配对（`(seat+3)%6`）、200 分制进贡、分层造反、23 张埋底。
- 4 人引擎改动唯一标准：**70 项测试全绿 + 行为零变化**。

### 3.2 卡牌身份：两副牌必须带副序号

- CardDTO.id 从 `heart_A` 改为 `heart_A_0` / `heart_A_1`（副序号 0/1）。
- power/points 与副序号无关；比较逻辑只看 suit/rank/power，天然支持重复牌。
- 前端渲染时忽略副序号，仅当同一张牌同时出现在两个位置时才区分。

### 3.3 房间与房号隔离

- `create_room` 必带 `{mode: "p4"|"p6"}`；房号按模式生成：4 位（p4）/ 6 位（p6）。
- `join_room` 只凭房号位数即可判定目标模式；服务端再校验 room.mode，防止伪造。
- 座位数组长度随模式（4/6）；开局条件 = 座位坐满 + 全部在线 + 全部准备（沿用一期规则）。
- 模式选择一旦创建房间即锁定，中途不可换模式。

### 3.4 服务端权威边界（沿用一期，强调不破）

- 前端只提交意图（reveal/tribute_take/bury/play），一切裁决在服务端。
- 他方手牌一律不下发，只发 handCount 与公开信息（亮牌、已出牌、底牌）。
- 8 张同点拆两副真杠：由服务端校验"每次只能出 4 张同点数"，前端仅提示可拆分。
- 造反等级由服务端统计闲家方生效亮番人数后下发，前端只展示。

## 4. 技术选型与部署（不变）

- 后端 Node.js + ws；前端原生 HTML/CSS/JS；存储全内存。
- 部署拓扑不变：开发目录（New project，任意端口）与公网副本（deploy-live，8090）物理隔离。
- 二期开发期间公网零影响；上线时同步 deploy-live 并重启（短暂掉线）。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 4 人模式回归 | core 抽取只做"移动代码"，70 项测试回归门槛 |
| 重复牌 id 冲突 | 副序号进 id，全链路唯一 |
| 8 张同点真杠误判 | 服务端严格 4 张校验 + 单测覆盖 |
| 6 人时长/手牌拥挤 | 前端适配 17 张手牌与 5 对手布局（见 task-split F3） |
| 房间号伪造 | join 时位数 + mode 双重校验 |
| 决策未定项 | 见 docs/phase2/decision-list.md，未拍板前不实现对应逻辑 |
